# ClipShelf 0.5.2：审查问题修复

日期：2026-10-20。基于 0.5.1 修复两项 P2 问题，保留历史及图片加密格式。

## 重同步遗漏更新

接收逻辑提取为浏览器与 Node 测试共用的 `src/shelf-receiver.js`。全量请求进行期间，仅记录收到的最高版本；全量返回后，如果仍落后，则再次请求当前全量。不会缓存大量待重放正文。过期全量响应不会覆盖已经收到的新状态；失败请求会显示错误，等待下一次缺口再重试。

按审查时的隔离消息时序复现：原来服务端版本 5、界面版本 4，3 条记录仅显示 2 条。修复后通过两次全量请求收敛到双方版本 6，3 条全部显示。测试还覆盖期间多次新增与删除、晚到的旧全量、失败恢复及重复消息。

## 已淘汰正文驻留

`ShelfUpdates.items` 只保存元数据和正文摘要组成的小型描述，不保存完整旧正文。摘要保留精确 UTF-16 信息，能够区分未配对代理项等特殊字符串。摘要计算以原始存活记录为弱键缓存；主进程传入原始记录，避免每次生成新的 IPC 投影时重新扫描全部正文。

相同的 67 条大文本淘汰复现中，原强缓存继续保留 67,000,462 字节正文；修复后的强缓存正文为 0，仅保留 15,544 字节的描述。独立生命周期测试保留摘要缓存、淘汰原记录，再验证原始对象可被回收。强制 GC 仅用于该隔离测试，不用于应用或性能采样。

这表示移除了主进程差量缓存的额外强引用。垃圾回收和系统内存管理决定工作集何时下降；渲染进程仍持有最后显示的一份历史，直到下一次同步，不能把该结果解读为整个程序立即释放同等大小的物理 RAM。

## 验证结果

- 41 项 Node 测试通过，包含原有功能和本次新增的消息时序、失败恢复、尾部正文编辑、特殊 Unicode、弱引用回收及摘要复用测试。
- 摘要复用测试中，同一大文本经过 10 次新建 IPC 投影，正文只计算一次摘要；正文修改后重新计算并正常发布。
- 最终打包版 `--smoke` 通过界面、搜索、完整正文预览、编辑、撤销、隐藏更新、暂停到期、队列和图片缩放/旋转等检查。此次受控前台窗口激活被 Windows 阻止，自动按键送达项记录为 `not-run`，未计为实际自动粘贴验证。
- `--clipboard-integration` 通过真实系统位图、单个 PNG 文件采集、图片回写及原生像素核对、去重、助手恢复、未知来源保护；原剪贴板恢复结果为 `RESTORED`。
- `--startup-integration` 通过临时启动项注册、后台参数、移除及初始隐藏检查。未注销系统验证登录重启。
- ASAR 源码与当前源码逐文件相符；清单包含新的接收模块，排除参考安装包、测试输出、文档和构建目录。

## 性能复核

相同合成负载的一次打包版采样：连续入库 CPU 0.24%（12 个逻辑处理器整机口径），处于此前 0.5.1 的 0.22%–0.33% 采样区间。后台空闲私有提交 298.12 MiB，大图阶段私有提交峰值 653.14 MiB，呼出至两帧渲染 81.76ms。单次采样受系统状态影响，不据此声称整体性能进一步提高。
