# 0.5.7 快捷键与目标窗口粘贴修复（本地候选版）

验证日期：2026-10-21。此记录随 0.5.7 源码提交。

## 改动

- 快捷键触发时由主进程同步保存前台窗口，避免等待助手响应时捕获到自己的面板；同一次按键保持锁存到 V 松开，避免系统重复触发造成开关反复切换。
- 原生窗口显示时启动一次入场动画，面板准备消息只更新内容；隐藏时将内容透明度复位，避免下一次显示先画出完整面板再重播动画。
- 双击后先等待鼠标和修饰键松开，再由当前前台的 Electron 进程调用 `AllowSetForegroundWindow`，把激活权限交给指定 Windows 助手进程。助手恢复原目标、确认目标处理了激活消息，再通过 `SendInput` 发送 Ctrl+V。
- 移除 `AttachThreadInput`；目标失效、前台已切换或激活失败时取消发送按键，并保留已复制内容。
- PowerShell 后备助手使用相同协议，并补充 UTF-8 BOM 以兼容 Windows PowerShell 5.1 的中文源码读取。

- x64 原生助手构建及 0.5.7 便携版打包通过，文件版本和产品版本均为 0.5.7。

- PowerShell 后备助手能够编译启动，`WAIT_KEYS` 和前台窗口查询通过；打包资源与源码 SHA-256 一致。

## 实际粘贴验收范围

新增 `--paste-integration`，使用独立 Windows 进程的两个文本框。通过真实生产粘贴处理器执行三次插入，断言第一框不变、第二框在原光标位置累加文本；双击由渲染器事件派发，测试打开面板时由合成接收程序交接前台权限。此模式不同于人工全局快捷键与物理双击的完整验收。

接收窗口须先获得前台焦点，测试才创建合成剪贴板内容；测试完成后在剪贴板仍归本次测试所有时恢复原内容。若前台激活失败，该项会超时失败，不应将其写作粘贴通过。

实际使用验收（2026-10-21）：用户在正常目标文本框中通过 Ctrl+Shift+V 呼出 0.5.7，并双击卡片后确认粘贴通过。独立自动化验收没有跑完：首次运行时 Windows 锁屏遮住了接收窗口；解锁后，自动化操作又被物理 Esc 中止。因此三次合成文本框回归没有计为通过，手工复测结果按用户反馈记录。
