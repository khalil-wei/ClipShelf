# ClipShelf 0.5.8：精简与唤起优化

日期：2026-10-26。本轮保持原有本地功能和历史格式，未引入新的运行时依赖。

## 实现

- 通过现有 Koffi 直接读取前台窗口及矩形，呼出不再等待 Windows 助手的串行请求。目标捕获、按键锁存和粘贴权限交接仍保留。窗口坐标不变时跳过 `setBounds`。
- 卡片 IPC 每条最多 650 个 UTF-16 字符，完整正文只在主进程保留；字符数单独传递。预览、编辑时按 ID 读取全文，未就绪时禁用正文输入和保存。关闭后释放全文，过期回复按请求号丢弃。
- 全文搜索仍涵盖正文、标题和来源。每批最多 32 条或累计约 512 Ki 字符后让出主线程，过期搜索取消；界面忽略乱序回复，等待期间不允许选择旧结果。
- 差量缓存仍以原始完整正文摘要判断变更，正文尾部编辑不会因预览相同而漏发更新。
- 大型历史序列化与大图一样，工作线程空闲 5 秒回收，普通任务保留原有 15 秒复用时间。不强制 GC、不主动清空工作集。
- 关闭系统 acrylic 合成和拼写检查，保留硬件加速、预热窗口与动画。实测开启后台节流后首次呼出变慢，最终保留原来的 `backgroundThrottling: false`；隐藏时仍由应用停止渲染和动画。
- 打包仅保留 en-US、zh-CN、zh-TW 三种语言资源；保留运行时 DLL、GPU 回退组件和许可证。`npm run pack` 可重复生成同样的目录布局。

## 同机对比

Windows、i5-11400H、12 个逻辑处理器、32 GiB RAM，Electron 42.11.15。0.5.7 使用提交 `41bd766` 的源码快照，仅换用相同测量脚本和同一编译助手；两者均为开发入口，顺序独立运行。数据为 1,850 条短文本、60 条长文本，加 36 次后台新增，共约 48 MiB UTF-8 正文。它是压力场景，不代表普通用户的常驻内存。

| 指标 | 0.5.7 | 0.5.8 |
| --- | ---: | ---: |
| 隐藏期间新增后呼出，最新卡片可见并再渲染两帧 | 192.03 ms | 108.67 ms |
| 后续 8 次呼出范围 | 35.93–43.97 ms | 30.04–45.20 ms |
| 后台空闲末端私有提交 | 580.27 MiB | 400.02 MiB |
| 面板可见空闲末端私有提交 | 754.30 MiB | 516.91 MiB |
| 大图后等待 10 秒末端私有提交 | 484.80 MiB | 321.21 MiB |
| 后台空闲 CPU，整机口径 | 0.02% | 0.10% |
| 连续新增 CPU，整机口径 | 0.75% | 0.83% |
| 列表传输正文字符数 | 17,293,010 | 831,540 |
| 快速滚动帧间隔 p95 | 11.7 ms | 11.8 ms |
| 打包目录大小 | 358.88 MiB | 313.35 MiB |

本组压力场景中，后台末端私有提交下降约 31%，列表正文传输量下降约 95%，首次显示最新历史耗时下降约 43%。常规重复呼出及滚动没有稳定的明显提升；CPU 没有下降证据，不能宣传为零占用。旧版标准场景（约 4 MiB 长文本）的后台末端私有提交约 302 MiB，不应拿它和新版 48 MiB 压力场景直接比较。

进程组包括 Electron 主进程、渲染/GPU/工具进程和原生助手。CPU 是进程组 CPU 时间除以墙钟时间和逻辑核数；每 250ms 由独立 PowerShell 采样，其进程不计入统计。私有提交不等于独占物理 RAM；工作集合计会重复计算共享页，原始记录中另有工作集数据。没有强制 GC。低 CPU 读数受计数分辨率、线程退出及桌面负载影响。首帧探针检查最新卡片实际存在，不把选中项是否保留当作渲染完成条件；不包含完整 235ms 动画结束。

## 验证与复现

- `npm test`：56 项测试，覆盖原功能、长文本摘要、完整正文尾部匹配、正文尾部差量变更、搜索乱序/取消、分批让出及大型历史线程回收。
- `npm run smoke` / 打包版 `--smoke`：隔离历史，验证全文搜索、按需长文本完整预览/编辑、加载完成前禁止保存、呼出绕过助手 BOUNDS 队列，以及原有图片、分组、队列、动画、加密等流程。
- 普通 smoke 不向用户应用实际发送粘贴；此次未重新进行实际文本框的 Ctrl+Shift+V 人工验收。0.5.7 的人工验收结论仅属于此前版本。
- `npm run perf -- --perf-large-history --perf-label=local` 运行同类压力场景；省略 `--perf-large-history` 使用标准场景。测试只使用合成历史，不读写用户剪贴板内容和历史。
- 本地原始对比记录：`artifacts/perf-source-v0.5.7/test-artifacts/performance-large-baseline-0.5.7.json` 与 `test-artifacts/performance-large-final-0.5.8.json`。基线源码快照为 `artifacts/perf-source-v0.5.7.zip`，测量脚本为当前 `src/performance.cjs`。

## 体积与基础占用限制

Electron 主程序本身约 223 MiB，裁剪语言包无法消除 Chromium/Node、多进程和 V8 的基础成本。本轮减少重复正文和多余资源，仍不等于原生小工具的体积或内存。若下一阶段目标是几十 MB 级常驻及显著更小的下载包，需要迁移到 Windows 原生界面和常驻服务；应保留现有加密历史、隐私规则及粘贴焦点回归，单独迁移与验收。
