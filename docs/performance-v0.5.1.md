# ClipShelf 0.5.1：CPU、内存与后台性能

日期：2026-10-19。在 0.5.0 上优化的补丁版本，不迁移历史加密格式。

## 已完成的优化

1. **隐藏面板停止接收历史更新。** 打开时同步最新变化；可见时仅传发生变化的记录及项目顺序。保留完整正文搜索、编辑及预览。差量携带基准版本，版本不符会重新同步，过期响应不会覆盖新状态。
2. **大图按块流式编码。** 取消工作线程中的整图像素复制与整图扫描行缓冲区，常规尺寸下扫描行块控制在约 512 KiB；输出 PNG 转移所有权，不再复制回主线程。不透明像素跳过透明度换算，保留透明像素及双向旋转精度。压缩输出仍受 16 MiB 限制。
3. **工作线程按需启动与回收。** 普通任务结束后空闲 15 秒回收；处理过大图的线程空闲 5 秒回收，再有任务时重建。任务运行时不会回收，异常恢复仍不重放旧任务。
4. **减少常驻宿主和唤醒。** Windows 助手编译成独立的 C# 程序，使用系统 .NET Framework，替代常驻 PowerShell 宿主。事件正常时每 5 秒校验序列号，事件不可用时仍以 750ms 兜底。暂停到期由单次定时器触发。
5. **降低撤销与预览开销。** 撤销共享不可变正文，只复制可变元数据；关闭图片预览时移除全图、正文及回调引用。隐藏事件明确停止动画和待执行渲染；保留渲染进程，避免每次呼出重新建窗。
6. **减少重复绘制。** 同一帧的状态更新与直接渲染合并；横向滚动过程中，新卡片直接进入可见区域，停止叠加入场淡入动画。呼出、收起、悬停和选中反馈保留。

## 测量方法

- 硬件：Intel Core i5-11400H，12 个逻辑处理器，32 GiB RAM；Windows 本机。基线和成品都使用 Electron 42.11.15。
- 0.5.0 保留原业务实现，只加入与新版相同的隔离测量入口，再打包运行。原 `dist/v0.5` 成品保留。基线源码快照在 `artifacts/performance-baseline-0.5.0.zip`。
- 合成 1,850 条短文本、16 条合计约 4 MiB 的长文本，再每 100ms 新增一条，共新增 36 条。打开面板确认最新记录可见，采样空闲、连续新增及快速横向滚动。
- 图片负载是 2048×8192、不透明、低复杂度长图，连续编码 3 次。它不代表高噪声照片、所有截图软件或全部机器的结果。真实系统位图采集及回写另由集成测试覆盖。
- 每 250ms 用 Windows `Get-Process` 采集 Electron 主进程、渲染进程、GPU/工具进程及 Windows 助手的 CPU 累计时间、工作集与私有提交。采样用的 PowerShell 进程不计入，但采样本身的开销并非完全为零。没有强制 GC，也没有清理用户历史。
- CPU 百分比为进程组 CPU 时间 ÷ 测量时长 ÷ 12。私有提交包含尚未驻留 RAM 的页；工作集会重复计算进程间共享页，不能当成独占物理内存。峰值是采样峰值，可能漏掉短于采样间隔的尖峰。空闲 CPU 接近计数分辨率，应看量级。
- 不计入启动预热和退出保存；测量模式只查询剪贴板序列号，不读取、修改用户剪贴板内容、历史或自启动设置。

## 打包版实测

主表采用最后一组顺序运行的基线与最终成品，均为打包版。

| 指标 | 0.5.0 | 0.5.1 |
| --- | ---: | ---: |
| 后台空闲 CPU（整机口径） | 0.08 % | 0.11 % |
| 连续新增 36 条时 CPU（整机口径） | 3.69 % | 0.33 % |
| 面板可见空闲 CPU（整机口径） | 0.21 % | 0.11 % |
| 后台空闲末端私有提交 | 345.9 MiB | 293.3 MiB |
| 后台空闲末端工作集合计 | 496.1 MiB | 422.8 MiB |
| 大图阶段私有提交采样峰值 | 1002.8 MiB | 624.5 MiB |
| 大图阶段工作集合计采样峰值 | 1041.1 MiB | 749.6 MiB |
| 3 次大图编码阶段总 CPU 时间 | 1671.9 ms | 1281.3 ms |
| 单图编码平均耗时 | 505.3 ms | 399.5 ms |
| 呼出至两帧渲染 | 95.5 ms | 121.4 ms |
| 快速滚动帧间隔 p95 | 13.8 ms | 13.5 ms |

这组场景中，连续入库的平均 CPU 下降约 91%，大图私有提交峰值下降约 38%，大图编码总 CPU 时间下降约 23%。呼出耗时从约 95ms 增至约 121ms，尚未优化成功；快速滚动没有测出稳定的明显提升。呼出计时包含窗口激活到两帧渲染，不是完整 235ms 动画的结束时间。

同一最终成品另一次测量：连续入库 CPU 0.22%，后台私有提交 296.4 MiB，工作集合计 499.4 MiB；大图私有提交峰值 658.3 MiB，工作集峰值 865.6 MiB。工作集受共享页和系统状态影响较大，不能仅凭一次工作集读数推断独占 RAM。空闲 CPU 也没有稳定下降的证据。


## 验证

- 33 项 Node 测试通过：包括流式 PNG 跨块边界、透明度、左右旋转、压缩超限后的恢复、工作线程空闲回收后重建、差量同步、撤销快照，以及原有隐私、分组、队列、持久化与助手重连回归。
- 最终打包版 `--smoke` 通过。新增验证隐藏期间复制后可搜索完整正文、预览正文未截断、暂停自动到期恢复、关闭图片预览释放引用。原有界面操作、图片缩放/旋转/撤销、加密保存和受控目标窗口自动粘贴通过。
- 最终打包版 `--clipboard-integration` 通过：真实系统位图和单个 PNG 文件入库、原生像素核对、图片回写、去重、助手被终止后恢复、来源不明时的应用排除保护。记录为 `RESTORED`，原剪贴板已恢复；不声称实际操作过微信界面。
- 最终打包版 `--startup-integration` 通过：临时注册、后台参数、移除和窗口初始隐藏。临时启动项已移除；未注销系统测试真实登录重启。
- 最终 ASAR 清单排除参考安装包、逆向材料、测试输出、文档与构建目录。版本、文件哈希和验证状态见 `artifacts/release-v5.1.json`。

## 仍值得优化的地方

- **主线程同步步骤。** 位图提取/缩放、账户加密及部分 IPC 复制仍在主线程；大图操作仍可能出现几十毫秒的停顿。下一步应分别测这几段，再决定采用后台图像处理还是调整存储编码。
- **正文的两份驻留。** 当前主进程和渲染进程仍持有完整历史正文。差量传输减少了重复复制；接近 64 MiB 文本预算时，仍可通过后台全文索引、按需取正文进一步降低内存。
- **面板呼出与快速滚动。** 需要继续拆分窗口激活、首帧、卡片创建和系统合成时间；本轮不承诺这些指标全部变快，也不声称达到 Paste 原版逐帧效果。
- **更多工作负载。** 应补充高噪声大图、真实应用连续复制、长期驻留和冷启动测试；本轮的合成场景不能取代这些测量。

## 使用与复现

成品为 `dist/v0.5.1/ClipShelf-win32-x64/ClipShelf.exe`。保留同目录文件，先退出托盘中的旧版。历史继续使用 `%APPDATA%/ClipShelf`。如果原来开启了自启动，在新版设置中重新启用一次，更新便携目录路径。

开发环境：`npm ci`、`npm run build:native`、`npm test`、`npm run perf -- --perf-label=local`。打包：`npm run pack`。成品也可直接运行 `ClipShelf.exe --performance --perf-label=local`；结果写在程序旁 `test-artifacts/performance-local.json`，需要该目录可写。

原始采样副本和汇总位于 `artifacts/performance-*-0.5.*.json` 与 `artifacts/performance-comparison-v0.5.1.json`。功能报告为 `artifacts/verification-v5.1-packaged.json`、`artifacts/clipboard-integration-v5.1-packaged.json`，完整运行日志为 `artifacts/packaged-v5.1-*.log`。
